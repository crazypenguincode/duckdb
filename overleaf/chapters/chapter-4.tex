\chapter{多策略协调的缓存替换技术}

本章详细介绍了多策略协调的缓存替换技术的设计与实现，作为第三章基于布隆过滤器的SQL和CTE动态缓存技术的重要支撑部分。该策略系统基于DuckDB的缓存管理框架实现，通过多种替换策略的协调配合，实现了高效的缓存管理和智能决策。系统主要包括基于LRU策略（LRU）、生存时间策略（TTL）、基于机器学习策略（MLIntelligent）的核心替换技术，混合策略是将这些策略根据不同条件使用达到多策略协调的目的。

\section{设计概要}

\subsection{系统架构设计}

智能缓存替换策略系统基于第三章介绍的QueryCache框架，通过CacheEvictionStrategy枚举定义了多种替换策略类型，包括TTL\_BASED、LRU\_BASED和ML\_BASED三种核心策略。系统采用策略模式设计，支持运行时动态切换和组合不同的替换策略。CacheEvictionStrategy枚举为系统提供了清晰的策略分类，每种策略都有其特定的适用场景和优化目标。

策略协调机制是系统架构的核心组成部分，通过设置淘汰策略方法（SetEvictionStrategy()）实现策略的动态切换，每种策略都有独立的评估机制和执行逻辑。按需淘汰方法（EvictIfNeeded()）作为统一入口，根据当前配置的策略类型调用相应的淘汰算法，保证了系统的灵活性和不同策略之间的无缝切换。系统通过策略工厂模式创建具体的策略实例，通过观察者模式监控策略执行效果，通过适配器模式统一不同策略的接口，实现了高度的模块化和可扩展性。



\subsection{核心设计理念}

容量检查机制监控缓存条目数量与内存占用：当缓存大小（cache.Size())超过配置的最大条目数（max\_entries）或内存使用量（CalculateMemoryUsage())超过最大内存字节数（max\_memory\_bytes）时触发淘汰，保证简单可靠的容量控制。

批量淘汰执行是淘汰流程的最后阶段，为了提高效率和减少系统开销，系统采用批量淘汰策略。批量大小根据当前的内存压力和系统负载动态调整，在资源紧张时增加批量大小以快速释放空间，在资源充足时减少批量大小以保持缓存的稳定性。批量淘汰过程中，系统会暂时锁定相关的缓存区域，避免并发访问导致的数据不一致问题。淘汰完成后，系统更新相应的统计计数器，包括各策略的淘汰次数、释放的内存空间、淘汰的条目数量等，为性能监控和策略优化提供数据支持。



\subsection{更新与替换流程算法}

\begin{algorithm}[htbp]
\caption{命中与插入流程}
\label{alg4_4_1}
\Require {query\_string}
\Ensure {result, was\_hit}
\begin{algorithmic}[1]
\STATE key $\leftarrow$ Hash(Normalize(query\_string)) \Comment{保证语义等价查询映射一致}
\STATE entry $\leftarrow$ cache.Find(key) \Comment{从缓存查找缓存条目是否命中，避免重复计算}
\STATE if entry = NULL then
\STATE result $\leftarrow$ ExecuteQuery(query\_string) \Comment{未命中则执行查询以获取最新结果}
\STATE features $\leftarrow$ ExtractMLFeatures(query\_string, result) \Comment{提取特征用于评分与后续在线学习}
\STATE new\_entry $\leftarrow$ NewCacheEntry(result, now, features) \Comment{构建缓存条目记录元数据}
\STATE switch config.eviction\_strategy do \Comment{根据当前策略设定淘汰优先级}
\STATE case ML\_BASED:
\STATE new\_entry.ml\_score $\leftarrow$ Predict(features) \Comment{通过模型对未来价值打分}
\STATE case LRU\_BASED:
\STATE new\_entry.eviction\_priority $\leftarrow$ now.time\_since\_epoch() \Comment{体现LRU优先级}
\STATE case TTL\_BASED:
\STATE new\_entry.eviction\_priority $\leftarrow$ new\_entry.created\_at.time\_since\_epoch() 
\STATE end switch
\STATE cache.Put(key, new\_entry) \Comment{写入缓存以供后续命中}
\STATE bloom\_filter.Add(key) \Comment{更新布隆过滤器降低查找成本}
\STATE RecordAccess(key, features, was\_hit=false) \Comment{记录未命中样本，支撑在线学习}
\STATE UpdateAdaptiveTuning() \Comment{根据当前指标自适应调参，抑制策略抖动}
\STATE EvictIfNeeded() \Comment{如超限则触发统一淘汰入口}
\STATE else
\STATE if IsExpired(entry) then \Comment{访问时被动过期检查：过期立即清理并视为未命中}
\STATE cache.Remove(key) \Comment{释放空间，避免无效占用}
\STATE result $\leftarrow$ ExecuteQuery(query\_string)
\STATE goto lines 5-21 \Comment{回到插入流程，完成新条目写入}
\STATE end if
\STATE entry.last\_accessed $\leftarrow$ now \Comment{命中路径更新最近访问时间，维持LRU有效性}
\STATE entry.access\_count++ \Comment{累加访问次数，反映条目热度}
\STATE entry.ml\_features.temporal\_locality $\leftarrow$ f(now - entry.last\_accessed) \Comment{用于ML评估}
\STATE entry.ml\_features.access\_frequency $\leftarrow$ entry.access\_count \Comment{更新访问频率特征}
\STATE RecordAccess(key, entry.ml\_features, was\_hit=true) \Comment{记录命中样本}
\STATE UpdateAdaptiveTuning() \Comment{即时调优以快速适应负载变化}
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[H]
\caption{统一淘汰流程}
\label{alg4_4_2}
\Require {由EvictIfNeeded触发}
\Ensure {更新缓存与统计}
\begin{algorithmic}[1]
\STATE RemoveExpiredEntries() \Comment{先清理过期条目，避免无效占用影响决策}
\STATE current\_memory $\leftarrow$ Sum(CalculateMemoryUsage(entry.result)) \Comment{估算当前内存占用，为容量/内存约束提供依据}
\STATE while cache.Size() > max\_entries OR current\_memory > max\_memory\_bytes do
\STATE switch config.eviction\_strategy do \Comment{按当前策略选择优先淘汰对象}
\STATE case TTL\_BASED:
\STATE oldest $\leftarrow$ argmin(created\_at) \Comment{以创建时间排序，优先释放最早条目}
\STATE current\_memory -= Memory(oldest) \Comment{删除后及时扣减内存估算}
\STATE cache.Remove(oldest) \Comment{执行删除以释放空间}
\STATE stats.ttl\_evictions++ \Comment{记录TTL策略的淘汰次数}
\STATE case LRU\_BASED:
\STATE lru $\leftarrow$ argmin(last\_accessed) \Comment{以最近访问时间排序，淘汰最久未访问条目}
\STATE current\_memory -= Memory(lru) \Comment{扣减LRU条目的内存占用}
\STATE cache.Remove(lru) \Comment{移除LRU条目}
\STATE stats.lru\_evictions++ \Comment{记录LRU策略的淘汰次数}
\STATE case ML\_BASED:
\STATE worst $\leftarrow$ argmin(ml\_score) \Comment{以机器学习评分排序，优先移除低价值条目}
\STATE current\_memory -= Memory(worst) \Comment{扣减低价值条目的内存占用}
\STATE cache.Remove(worst) \Comment{移除低价值条目}
\STATE stats.ml\_evictions++ \Comment{记录ML策略的淘汰次数}
\STATE end switch
\STATE end while
\STATE if config.eviction\_strategy = ML\_BASED then
\STATE UpdateMLModel() \Comment{根据访问历史更新模型，保持评分新鲜}
\STATE end if
\end{algorithmic}
\end{algorithm}

系统采用生存时间（TTL）过期机制；EvictByTTL/LRU/ML分别线性扫描选择最早创建、最久未访问或最低ml\_score的条目并逐个淘汰；记录访问/模型更新函数（RecordAccess/UpdateMLModel）构成在线学习闭环（线性权重+sigmoid+学习率衰减）；自适应参数调优器（AdaptiveParameterTuner）可按指标在TTL\_BASED、LRU\_BASED、ML\_BASED之间自适应切换。

\section{智能缓存替换技术}

\subsection{基于LRU的动态缓存管理技术}

基于LRU（Least Recently Used）的动态缓存管理技术是缓存系统中最经典和广泛应用的策略之一，基于时间局部性原理，认为最近访问的数据在未来被访问的概率更高。本系统中的LRU算法是基于DuckDB优先级队列的多层次LRU替换算法，策略通过EvictByLRU()方法实现，针对数据库查询缓存的特点进行了多项优化，包括访问时间的高精度跟踪、多维度的访问统计和智能化的淘汰决策等，与其他策略协同工作，为缓存系统提供了稳定可靠的基础淘汰能力。

使用高性能无锁并发队列支持多线程并发访问，通过智能的死节点清理机制（每4096次插入触发批量清理8192个节点）和自适应清理策略（根据活节点与死节点比例动态调整）保持队列健康。淘汰时按优先级从高到低遍历队列，通过序列号验证确保淘汰最久未访问的块，并支持内存直接复用优化，整体设计在保证LRU语义的同时实现了极高的并发性能和低锁竞争。

\subsection{基于时间策略的动态缓存管理技术}

基于生存时间策略的动态缓存管理以全局生存时间（global\_TTL）为时效控制基线：在访问路径进行被动过期检测，在淘汰入口进行机会式清理，无需后台线程即可保持缓存洁净；当容量或内存超限时，通过批量扫描有效回收长期未访问的失效条目。TTL参数依据命中率（hit\_rate）、查询耗时趋势（query\_latency\_trend）与内存压力（memory\_pressure）进行渐进式调优，以在稳定性与空间回收效率之间取得平衡。

\subsection{基于机器学习策略的动态缓存管理技术}

本节仅实现了轻量级的机器学习缓存策略：采用线性权重配合 sigmoid 的评分模型，结合在线学习形成低开销闭环，旨在为高并发场景提供可解释、可调的价值评估。模型在命中与未命中路径中持续收集访问样本，以时间衰减控制历史影响，保持对近期模式的敏感性。

以“评分驱动淘汰”为核心：对每个条目计算缓存价值分数，低分对象优先被移除，以在内存受限时腾挪空间。该策略侧重将执行成本、结果大小、访问热度等信号转化为统一的价值度量，避免复杂的多策略融合带来的额外开销。

\textbf{当前实现方案与架构扩展性}

本系统采用\textbf{轻量级线性评分模型}作为当前实现方案，通过9维特征向量（查询复杂度、执行时间、结果大小、访问频率、时间局部性、表数量、连接数量、聚合和子查询标识）进行线性加权求和，配合Sigmoid激活函数将评分映射到[0,1]区间，并使用带学习率衰减的梯度下降算法实现在线学习。该模型具有计算开销低、可解释性强、无需离线训练等优势，适合高并发场景下的实时缓存价值评估。

同时，系统在架构设计上充分考虑了可扩展性，预留了完整的高级模型接口，包括\textbf{Adam优化器}（支持自适应学习率和动量优化）、\textbf{Holt-Winters时间序列预测器}（捕捉周期性访问模式）、\textbf{多因素价值评估器}（支持5维权重管理）和\textbf{在线学习管理器}（集成置信度评估和多策略融合决策）。为未来采用深度学习、强化学习等更先进的机器学习技术预留了清晰的技术升级路径，实现了模块化、配置驱动的渐进式演进架构。

\textbf{特征工程与模型训练}

基于上述设计理念，系统集成机器学习技术，通过查询特征与访问模式的分析，为条目价值评分提供依据：复杂度与执行成本反映"计算开销节省"，结果大小体现"内存占用权衡"，而访问频率与时间分布刻画"未来命中概率"。这些信号共同影响评分与淘汰优先级，在资源紧张时帮助系统更快释放低收益条目、保留高收益条目。

特征工程是机器学习策略的基础环节，系统从查询语句、执行统计、访问模式、系统状态等多个维度提取特征，形成高维特征向量。查询语句特征包括语法结构特征，如查询长度、表数量)、连接数量、聚合函数数量（aggregate\_count）等，这些特征反映了查询的复杂度和计算成本。语义特征包括查询类型、数据访问模式、结果集特征等，这些特征反映了查询的业务含义和数据特征。执行统计特征包括执行时间、CPU使用率、内存消耗、I/O开销等，这些特征反映了查询的资源需求和性能特征。访问模式特征包括访问频率、访问间隔、访问时间分布、用户行为等，这些特征反映了查询的使用模式和重要性。系统状态特征包括当前负载、内存压力、缓存状态等，这些特征反映了系统的运行环境和资源状况。

模型训练采用在线学习：访问记录函数（RecordAccess）记录访问样本，模型更新函数（UpdateMLModel）基于队列样本计算效用并调用机器学习缓存预测器更新方法（MLCachePredictor::Update（features, actual\_utility）)。预测器通过线性权重与sigmoid评分，使用梯度下降并带学习率衰减；

预测决策是机器学习策略的核心应用，系统根据模型预测结果计算缓存条目的价值评分（value\_score），指导缓存插入和淘汰决策。预测过程首先提取查询的特征向量，然后通过训练好的模型计算缓存价值评分。评分结果表示查询结果被缓存的预期收益，包括未来访问概率、计算成本节省、资源利用效率等因素。预测决策不仅考虑单个查询的价值，还考虑缓存空间的整体利用效率，通过优化算法选择最优的缓存条目组合。预测结果还包括置信度估计，帮助系统判断预测的可靠性，在置信度较低时可以结合其他策略进行决策。

\section{本章小结}

本章详细介绍了智能缓存替换策略的设计与实现，作为第三章动态缓存管理系统的重要组成部分。系统主要包括基于LRU策略（LRU）、生存时间策略（TTL）、基于机器学习策略（MLIntelligent）的核心替换技术。通过多策略协调机制，系统可以根据不同条件在这些策略之间动态切换，达到自适应的缓存管理目的。

系统采用策略驱动和自适应参数调优的方式，在不同负载下动态切换LRU/TTL/ML策略，实现自适应的缓存管理与性能优化。机器学习策略通过特征工程和反馈学习持续优化预测准确性。
